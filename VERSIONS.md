## How the captures are taken

The release binaries run as local processes: Fabric CAs, orderers and peers, with chaincode
started by the peer through an external builder (Node.js chaincode as a process, or chaincode
as a service). No container is involved. Readers run the same commands under Docker Compose.
Command output is the same apart from host names, ports and paths, which the capture scripts
rewrite to the Compose names. Where an output only exists under Docker, such as
`docker compose ps`, the book shows the command without its output.

From Chapter 5 on, the Compose files themselves drive the captures: `tools/native/compose-native.py`
resolves them with `docker compose config` (the Compose CLI works without a daemon) and runs each
service as a local process with the environment, command and ports the file gives it. The Compose
files are therefore the configuration the book prints, but they have not been run under a Docker
daemon on the authoring machine, and the chaincode image has not been built there.

## Secrets

No key, certificate or password is committed. Identities are generated by Fabric CA at run
time into folders that `.gitignore` excludes. The CA bootstrap passwords in the scripts are for
local networks only.
